## 二、优化方案详情

### 2.1 API缓存策略 ⭐优先级：高

#### 方案一：ISR (Incremental Static Regeneration) - 推荐

**原理**: 利用Next.js的静态生成+增量重新生成机制

**适用场景**: 数据更新频率较低（小时级/天级）

**实现方式**:
```tsx
// src/pages/api/links.ts 添加 revalidate 导出
export const revalidate = 3600 // 每小时重新生成一次

export default async function handler(req, res) {
  // 现有逻辑保持不变
  // Next.js 会自动缓存输出，每小时最多重新生成一次
}
```

**优点**:
- 🚀 大幅提升页面加载速度
- 🔄 减轻飞书API压力
- ⚡ 部署简单，无需额外基础设施

**缺点**:
- ⏱️ 数据可能有最多1小时的延迟
- 📝 如果流量大，可能触发Vercel带宽限制

#### 方案二：On-Demand Revalidation

**原理**: 数据更新时手动触发缓存失效

**实现方式**:
```tsx
// 添加一个触发重新生成的API端点
// src/pages/api/revalidate.ts
export default async function handler(req, res) {
  if (req.query.secret !== process.env.REVALIDATE_SECRET) {
    return res.status(401).json({ message: 'Invalid token' })
  }
  
  try {
    await res.revalidate('/')
    await res.revalidate('/sitemap.xml')
    return res.json({ revalidated: true, now: Date.now() })
  } catch (err) {
    return res.status(500).json({ message: 'Error revalidating' })
  }
}
```

**触发方式**: 在飞书多维表格更新后，调用 `https://your-site.com/api/revalidate?secret=xxx`

#### 方案三：SWR (Stale-While-Revalidate)

**原理**: 返回缓存数据的同时在后台进行数据更新

**适用场景**: 需要实时数据但又想利用缓存

**实现方式**:
```tsx
// 在 index.tsx 中使用 SWR
import useSWR from 'swr'

const fetcher = (url) => fetch(url).then(res => res.json())

function HomeContent() {
  const { data, error } = useSWR('/api/links', fetcher, {
    revalidateOnFocus: false,
    revalidateOnReconnect: true,
    dedupingInterval: 60000, // 1分钟内不重复请求
  })
  
  // 使用 data.links 和 data.categoryOrder
}
```

**需要安装**: `npm install swr`

### 2.3 图片优化 ⭐优先级：中

#### 方案：迁移到 next/image

**修改文件**: `src/pages/index.tsx`

**现有代码**:
```tsx
// 当前
<img src={link.icon} alt="" />
```

**优化后**:
```tsx
// 优化
import Image from 'next/image'

<Image 
  src={link.icon} 
  alt=""
  width={24}
  height={24}
  unoptimized={true} // 如果图标是外部URL
/>
```

**配置 next.config.js**:
```js
module.exports = {
  images: {
    domains: ['xxx.feishu.cn', 'cdn.yourdomain.com'],
    formats: ['image/webp', 'image/avif'],
  },
}
```

## 四、方案选择确认

### 4.1 API缓存策略确认

| 方案 | 适用场景 | 选择 |
|------|----------|------|
| ISR (revalidate) | 数据更新频率低（小时/天级） | ⬜ |
| On-Demand Revalidation | 需要手动控制更新时机 | ⬜ |
| SWR | 需要实时数据但想利用缓存 | ⬜ |
| 暂不实施 | 接受每次实时请求 | ⬜ |

### 4.2 缓存时间确认

如果选择 ISR，请确认缓存时间：

| 缓存时长 | 适用场景 | 推荐度 |
|----------|----------|--------|
| 60秒 (1分钟) | 数据频繁更新 | ⭐ |
| 300秒 (5分钟) | 适中更新频率 | ⭐⭐⭐ |
| 3600秒 (1小时) | 数据不常更新 | ⭐⭐⭐⭐⭐ |
| 86400秒 (24小时) | 数据几乎不变 | ⭐⭐ |
